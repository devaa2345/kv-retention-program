# Fresh-data M3 replication of the M2 focused-evidence SQuAD system

This is a prospective M3 confirmation of the **unmatched-memory** focused-evidence pipeline from `PREREG_REALTEXT_FOCUS_M2_DEV.md`, not a matched-memory experiment. The previously found M3 outputs on the M2 heldout manifest were uncommitted, not preregistered, and exposed to M2 results before M3 generation; `REALTEXT_FOCUS_M3_ARTIFACT_AUDIT.md` classifies them as exploratory. Their answers and effects do not set this test's prompt, pointer, mask, sample size, or decision rule.

## Data lock and size

The unchanged deterministic SQuAD constructor produced candidate indices 752–871. An answer-blind first-distinct-question filter selected 76 instances / 152 SQuAD queries, indices 752–862, with no SQuAD question reused from earlier real-text data. Manifest SHA-256 is `b63d3e3fab356fae074732f84da500e3aeace25b9e476fba7502e4d7742da095`. The 76-instance size comes from the original M2 focus development preregistration: its paired per-instance variance was 0.09677419, and its frozen 10-point sizing formula gave 76. The exploratory M3 output did not determine N. The context also contains synthetic codes, but only the two SQuAD questions per instance are generated and scored.

## Frozen M3 pipeline and pre-generation ceilings

M3 is `meta-llama/Llama-3.2-3B-Instruct` on RTX 5070, with the model's own tokenizer and A1 prompt. The four arms are plain `floor_pos`, plain `snapkv`, `floor_pos_focus_mask`, and `snapkv_focus_mask`. All use `round(0.2802*n_ctx)` retained prefill tokens **per KV head**, with the same 8-token sink, 64-token window and press builder as M2. The focused arms append their own selected eligible source sentence in the unchanged A1 focus format, then use the same `literal_v1` mask. Floor selects with last-prompt-token attention; SnapKV selects with the existing BM25 lexical pointer. Neither sees gold answers at inference. Focus additions are outside the prefill budget, recorded in tokens, and mean this is **not** a matched-total-KV claim. This model has 8 KV heads versus M2's 2, so absolute KV bytes across models are not equated.

The two prefill-only captures completed before any answer generation, using 1.26 GPU processing minutes after load each. Floor retained the gold sentence in 36/152 and its fixed pointer selected it in **33/152**. SnapKV retained it in 142/152 and its fixed pointer selected it in **118/152**. These are absolute one-sentence-mask ceilings, not expected answer counts. Floor capture SHA-256 is `dc64a06bf08e5c13841974ce1c22896b39e9a406739a0a2401faca042d0de517`; SnapKV capture SHA-256 is `32721a840bc2ce944501c86667836c445d20099c6bfe005ce5fde1bbbc0aebfd`.

## Checks and decision rule

Require all 152 queries in all four arms, with focused and unmasked pairs matching on keep-set hash, retention budget and held status. Each focused selected sentence must equal its saved prefill-only pointer prediction; each masked raw answer must be an exact substring of that selected sentence; corrected full-context invented values must be zero. Score whole answers with only casefold and whitespace-run normalization, never substring-contains scoring. Report all answer counts, pointer hits, held rates, mean/max focus extra tokens, cap stops, conversions/broken cases and measured GPU processing time. Estimate answer generation at 3–5 GPU processing minutes after model load.

For each comparison, average the two query-level score differences within each instance and draw 10,000 paired bootstrap resamples of **instances**, seed 5070. Claim a clean M3 focused-system SQuAD win only if **both** 95% CI lower bounds are greater than zero: focused SnapKV minus equally focused floor (primary control), and focused SnapKV minus plain floor (secondary control). Report focused SnapKV minus unmasked SnapKV and focused floor minus plain floor separately. This test does not license a matched-memory claim or any post-hoc pointer, prompt or scoring change.
