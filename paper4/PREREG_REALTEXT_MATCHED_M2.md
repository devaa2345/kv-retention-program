# M2 SQuAD matched-preanswer-KV focused-evidence test

The prior independent 76-instance SQuAD result established a focused-system win, but reinsertion added 43.86 SnapKV and 49.27 floor tokens per query outside the original retention budget. This new test asks whether SnapKV's focus method still beats floor when its total working KV **before the first answer token** is capped at or below the unmodified floor's, query by query. It is a separate experiment, not a reanalysis of the spent heldout data.

## Frozen development data and pre-generation ceilings

The answer-blind first-distinct-question filter selected 32 instances, 64 SQuAD questions, indices 604–650 with 15 duplicate-question skips. No earlier real-text question is reused. The prefill-only captures used a retention budget of `round(0.2802*n_ctx)-128` per head for both focused arms. They cost 0.50 floor and 0.49 SnapKV measured GPU processing minutes after model load. Floor held the gold sentence in 13/64 and its frozen last-token attention pointer selected it in **12/64**. SnapKV held it in 31/64 and its frozen BM25 lexical pointer selected it in **26/64**. These selected-sentence counts are absolute exact-answer ceilings under a one-sentence literal mask, not forecasts. Capture SHA-256 values are `95a24582d3150035ad1d44fe40a129dfa6733c2feb9fad80393f8b95733401f2` (floor) and `b554e79540808fb6b1806682590c1c54312640251854eb30a2791a6875ae3acd` (SnapKV).

## Frozen arms and budget accounting

All arms use M2 on RTX 5070, the unchanged A1 short-answer prompt and strict whole-answer exact-match scoring with only casefold and whitespace-run normalization. One instance contributes two SQuAD queries. The plain floor comparator uses `B0=round(0.2802*n_ctx)` retained prefill tokens and no focus, mask or pointer. The floor focus control and SnapKV arms use `B=B0-128`. The SnapKV unmasked arm at B is a within-retention baseline. The focused floor and SnapKV arms use their arm's selected eligible source sentence in the same focus format and `literal_v1` substring mask; there is no oracle sentence.

The focus reserve is **128 post-prefill tokens**, fixed from the prior development maxima (113) before inspecting this fresh set's answers. If a selected sentence makes the focused post-prefill query more than 128 tokens longer than A1, use the original A1 post-prefill query with the same selected-sentence literal mask. This fallback uses no answer or gold text. Record fallback and focus-token count. Assert on every query that `B + actual_post_tokens <= B0 + original_A1_post_tokens`. Thus focused arms use no more pre-answer working KV than plain floor per query; matching is a cap, not an assertion of equal actual use. Decode length may differ after the first answer token and is reported separately.

The development generation must complete all 64 queries in all four arms, preserve SnapKV keep-set and held status between its unmasked and focused rows, reproduce the prefill-only selected sentences for both focused arms, show each masked raw answer is an exact substring of its selected source sentence, and have zero corrected full-context invented values. Report retention, pointer hits, fallbacks, added tokens, and mean pre-answer KV by arm. Estimate development answer generation at about 1–2 GPU processing minutes after model load; report measured time.

## Decision rule, independent confirmation and claim

Proceed to an independent confirmation only if development SnapKV+matched-focus exceeds floor+matched-focus by at least **4/64** queries and all checks pass. Otherwise stop this particular method and report the result. If passed, use paired per-instance differences (the mean over each instance's two SQuAD queries) to compute `N_power=ceil((1.96+0.84)^2*s^2/0.10^2)` for a 10-point target, then `N=min(160,max(64,N_power))`; report any `N_power>160` limitation. Select fresh, globally distinct SQuAD questions starting after index 651, lock N, data hash, ceilings and unchanged code in a commit before any confirmation answers.

The independent confirmation needs **both** 95% paired instance-bootstrap CIs (10,000 resamples, seed 5070) for SnapKV+matched-focus minus floor+matched-focus and minus plain full-budget floor to have lower bounds >0 before claiming a matched-preanswer-KV SQuAD win. Also report SnapKV+matched-focus versus reduced-budget unmasked SnapKV, answer counts, conversions and broken cases, retention, pointer hits, mask validity, fallback count, cap stops and measured GPU time. This remains one model; M3 and RTX Pro 5000 are outside this test.

## Development gate and confirmation size

All four arms completed 64/64 development queries; selected sentences matched frozen capture predictions, all focused answers were exact source-sentence substrings, and both focused arms obeyed the per-query pre-answer KV cap. Correct counts were plain full-budget floor 8/64, reduced-budget unmasked SnapKV 8/64, reduced-budget focused floor 9/64, and reduced-budget focused SnapKV **15/64**. Focused SnapKV minus focused floor was +6/64, so the fixed +4/64 gate passed. The descriptive 95% instance-bootstrap CI was [0,+0.1875]; this is not a confirmation. Mean pre-answer KV was 646.03 plain floor, 567.84 focused floor and 558.92 focused SnapKV. No focus fallback fired. Development answer generation cost 1.35 measured GPU processing minutes after model load. The paired per-instance variance was 0.07157258, giving `N_power=57` and the frozen `N=64` instances/128 SQuAD queries.
